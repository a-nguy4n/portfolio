Weather Wardrobe

Your wardrobe, powered by the weather.

Overview

Weather Wardrobe is an IoT-powered wardrobe assistant that combines real-time temperature readings, weather forecasts, and AI to help users make everyday outfit decisions.

The application connects ESP32 temperature sensors to a personalized web dashboard, where users can register devices and view real-time temperature data. It also features an AI assistant that suggests outfits based on current weather conditions.

THE OBJECTIVE

Connecting physical sensors to everyday decisions.

The goal was to collect temperature data from an ESP32 device and use it to create an interactive dashboard integrated with AI. This would allow users to monitor real-time conditions and receive personalized outfit recommendations from their closet based on the weather.

Technical Implementation

SYSTEM ARCHITECTURE

How Weather Wardrobe works

The system connects an ESP32 sensor to a web application using MQTT and FastAPI. Users can view temperature data and receive AI-powered outfit suggestions.

01

Sensor Integration

The ESP32 collects real-time temperature readings and publishes them to an MQTT broker. This allows for asynchronous communication between the sensor and application backend.

02

Backend & Data

FastAPI manages REST API endpoints, device registration, and sensor data processing. The backend maintains user-device relationships and stores temperature readings for retrieval and visualization through the dashboard.

03

Weather & AI

The application combines external weather forecasts with AI-powered recommendations. By leveraging the current weather conditions and the user's wardrobe, the assistant generates personalized outfit suggestions.

Architecture Diagrams

01 / DATA MODEL

Entity-Relationship Diagram

The Entity-Relationship Diagram here outlines the database structure of Weather Wardrobe, consisting of four entities: users, devices, sensorData, and sessions.

  • Users: Stores account information and serves as the central entity connecting users to their registered devices, sensor readings, and sessions.
  • Devices: Stores each ESP32 device's owner, MQTT topic, and status, allowing users to register and manage multiple devices.
  • Sensor Data: Records sensor measurements, including the sensor type, value, and timestamp, supporting temperature monitoring and historical data retrieval.
  • Sessions: Tracks device activity using user and device references, along with session start and end times.

The database uses primary keys to uniquely identify records and foreign keys to establish relationships between entities. Its one-to-many relationships allow each user to manage multiple devices, accumulate sensor readings, and maintain activity records.

This relational structure supports device management, data storage, and temperature visualization while keeping user information and sensor activity organized.

03 / COMPONENTS

Component Diagram

The Component Diagram shows how Weather Wardrobe's hardware, backend, database, and external services communicate to collect, process, and store sensor data.

  • ESP32: Connects to the temperature sensor and collects readings from the physical environment.
  • MQTT Relay: Transmits sensor readings from the ESP32 to the application backend using MQTT messaging.
  • FastAPI: Serves as the central backend, receiving MQTT messages and HTTP requests while coordinating data processing and communication with other services.
  • Database: Stores application data and supports database read and write operations through FastAPI.
  • KV Storage: Provides key-value storage for cookies and temporary application data.
  • Deployment Platform: Hosts the FastAPI application and makes its backend services publicly accessible.

The system uses separate components to collect, process, and store data. FastAPI connects these components, handling incoming sensor readings and managing communication with the database and other services.

04 / USER FLOW

User Logic Flow Diagram

The User Logic Flow Diagram illustrates how users navigate through Weather Wardrobe. From the landing page, users can sign up or log in to access the dashboard, where they can view sensor readings, weather information, and AI outfit recommendations. Users can also manage their account and connected devices through the Profile page or organize their clothing through the Wardrobe page. Logging out returns users to the login page.

Synthesis & Takeaway

PROJECT REFLECTION

Connecting hardware and software.

Weather Wardrobe challenged me to think beyond individual features and focus on how different parts of an application work together. From managing communication between devices to organizing data and designing user interactions, the project required careful planning, testing, and troubleshooting. It also highlighted the importance of building a reliable system while keeping the experience simple and accessible for users.

TAKEAWAY

What I've learned

This project gave me hands-on experience building a full-stack application that communicates with physical hardware. I developed a stronger understanding of backend development and how data moves between connected systems.

One of the main challenges was integrating the ESP32 with the backend and ensuring sensor readings were processed and stored correctly. Troubleshooting this connection helped to reinforce my debugging skills and taught me how to approach problems across multiple components.

Overall, Weather Wardrobe helped me become more confident in building integrated applications and using AI to make collected data more useful.
